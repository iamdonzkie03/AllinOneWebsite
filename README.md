# Commonplace — Zamboanga Community Portal

A PHP/MySQL community portal focused on Zamboanga City's history and culture, creative arts and photography, local news, marketplace activity, entertainment and politics.

## Five public modules
1. Creative Arts and Photography
2. News Connect
3. Marketplace
4. Entertainment & Politics
5. History & Culture

The public homepage includes an automatically advancing Zamboanga City heritage slideshow featuring Fort Pilar, the waterfront, the vinta tradition, and Yakan weaving. The image captions link to their Wikimedia Commons source pages.

## Stack
- PHP 8.3+ (use a currently supported PHP release)
- MySQL 8+
- HTML5, CSS3, JavaScript, jQuery 3.x
- PDO prepared statements, password hashing, session-based authentication

## Three website areas and workflow
- **Viewer front end:** browse and search public content; only administrator-approved/published posts are visible.
- **User personal workspace:** a user registers with their name, email, password and contributor details. The account remains pending until the System Administrator approves it. After approval, the user can sign in and create, edit, delete, search, save drafts, and submit content for review.
- **System Administrator back end:** review account details, approve/reject account access, and publish/reject submitted content.

## Setup
1. Put the `allinoneweb` directory under your PHP server's web root.
2. Create a MySQL database and import `database/schema.sql`.
3. Copy `config/config.example.php` to `config/config.php` and set database credentials.
4. For an existing installation, take a database backup and run `database/migrations/2026-10-27-zamboanga-modules.sql` once to update categories while preserving existing content.
5. Open the site at `http://localhost/allinoneweb/`. The homepage `index.php` is in the project root; account and admin pages remain in `public/`.
6. Create the first administrator using a secure one-time setup process or insert a password hash generated by `password_hash()` into the users table. Do not leave a public default administrator password.
7. Enable HTTPS in production and set secure cookie/session options.

This remains a starter scaffold, not a production-ready deployment. Before public launch, add rate limiting, email verification, audit logging, file-upload scanning if uploads are added, backups, and deployment-specific hardening.
